PostgreSQL CDC Replication Pipeline

Streaming row-level Postgres changes to an analytics store with WAL, Debezium & Kafka

What I Did

Built an end-to-end change-data-capture pipeline that streams row-level changes out of PostgreSQL in real time. The pipeline chains five layers: PostgreSQL's write-ahead log (WAL) via logical replication slots, a Debezium connector that extracts change events and handles schema evolution, Kafka for fault-tolerant event streaming, a Python consumer that validates schemas, deduplicates events, and routes bad messages to a dead-letter queue, and a replica PostgreSQL analytics store on the receiving end. I wrote diagnostic scripts to detect replication slot bloat, LSN gaps, and schema drift, added continuous lag and queue-depth monitoring, and documented runbooks for each failure mode. The whole thing runs via Docker Compose and includes a harness for simulating 1,000+ events to exercise the pipeline under load.

Why I Did It

Replication lag and CDC failures are a recurring theme in my day job, so I wanted to build the whole pattern from scratch — WAL, Debezium, Kafka, dead-letter handling — to understand exactly where things break (slot bloat, missed transactions, schema drift) instead of only debugging someone else's pipeline. Treating failure modes as first-class, with runbooks and monitoring built in from the start, mirrors how I think CDC pipelines should be built in production.
